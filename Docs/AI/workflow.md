# 从用户输入到结果

|你要做的事|采用的公开入口|结果与边界|
|---|---|---|
|接入日志|BLF/ASC＋对应DBC；原始报文CSV需明确报文格式；已解码CSV按表头声明，内存输入用于可控数据|来源、时钟和实体范围属于输入契约。只在证据允许时联合多个来源。|
|构建分析|单次分析用版本3的YAML/JSON；公共定义复用限一层。读取文件用 load_analysis_plan，构造字典用 AnalysisPlan.from_dict|计划检查引用、类型、单位和时钟；可按需枚举目录或读DBC元数据。原始数据中的业务含义还未验证。|
|选择计算|用已绑定名称定义条件、派生表达式、规则、窗口和 calculations；逐消息累计另走 message_calculations|真实活动与片段可单独统计；积分方法、时间间隔与质量影响结果。|
|使用业务预设|在完整计划的 presets 中声明角色和参数；Python 构建预设返回 PlanFragment|预设展开为普通声明，角色校验不替你确定工程阈值；片段不是完整计划。|
|先解释再运行|validate_analysis_plan / explain_analysis_plan；AnalysisRunner.run|解释看到依赖、时间需求和预算，并非已经读取了那么多数据。run 在真实输入上计算，返回 AnalysisResult。|
|读取或交付|在 AnalysisResult 上流式迭代，并在结束或提前退出时关游标；write 发布到新目录，最后关闭结果|关联键和质量以各结果行类型为准，空值不等于零。发布失败不能报告已交付。|
|独立批量|load_batch_plan、run_batch 或 python -m chronaxis batch run|每个子任务独立；正常返回仍要读各项状态。不是把一个有状态会话切成多任务。|

本版正式输出发布的环境证据限于 Windows / Python 3.12。支持的旧格式、通道、导出及 profile 仍有条件；缺支持时保留 validate/explain 给出的能力限制，不承诺任意旧链可用。示例里的数值是合成数据，平台、预算、速度和真实业务判断应分别验证。

## 写配置前保留用户原意

先把用户已给出的条件对应到配置，不要求用户重新确认已有信息。以下例子来自“状态为 `0x2`、电流至少 `10A`，连续超过 `60s` 的区间内，积分电流乘电压，结果为 `kWh`”：

|需要保留的内容|配置与处理方式|
|---|---|
|信号与表达式|分别绑定 `BMS_ChrgSta`、`BMS_BatPackActCur`、`BMS_BatPackActVol`；计算电流乘电压，不换成其他测点的信号。|
|每个比较符与逻辑关系|条件为 `state == 0x2 and current >= 10`，别名分别指向上述状态和电流；保留等号、包含边界的 `>=` 和“且”。|
|连续超过60秒|使用 `condition_duration`、`minimum_duration: 60s`、`duration_comparison: ">"`。恰好60秒不合格；不能把阈值改为60.1秒，也不能只筛选每一帧而省略连续时长。|
|积分起点与结束|“合格区间内”采用默认 `selection_origin: onset`，从条件开始成立处累计到区间结束；不擅自丢掉前60秒。只有用户明确要求从持续确认之后算，才改用 `confirmed`。|
|单位|按DBC或已有定义核对电流为A、电压为V，计算项输出 `kWh`；不要把J或Wh的数值直接标成kWh。|
|文件关系和计时依据|连续分卷放在同一来源，状态跨文件延续；独立任务才使用批量入口。沿用已确定的实际间隔或固定/DBC周期，不用修改文件时间代替正确配置。|

别名可由配置取简短名称，但说明应给出别名对应的原信号。优先从输入、DBC、匹配的任务示例和已给出的要求取得事实；仅在仍缺少且会改变结果时确认，例如多个候选信号无法唯一匹配，或无法判断文件是连续分卷还是独立实验。支持的默认值直接采用并在必要处说明，不把每个可选字段都变成问题。

普通表达式积分不要求补充业务预设才使用的电流方向、测量位置等领域元数据。用户已指定原始电流比较和乘积时，不为了给结果命名为“充电”或“放电”而另加正负号转换；只有任务确实需要这种业务解释、且现有信息不足时才确认。

## 报错修复与核验范围

安装失败、缺依赖、路径或字段错误只修对应原因；保持上表中的信号、条件、持续门槛、积分起点和单位。不能为使程序跑通而增加方向/测点限制、`95%`覆盖率门槛、额外最小值/最大值统计，或调整有效期、阈值和计时方式。原始时间倒退等数据错误也不能自动排序、去重、过滤或重写输入；先给出真实诊断，确需处理数据时说明处理对结果的影响。

只执行本任务需要的读取、计算和交付。安装与公开入口校验通过后运行所需分析；用户未请求、计算也不需要的贡献明细、追溯、原帧副本、额外统计或重复扫描，不构造、不扫描、不保存、不输出。无事件或空结果按实际诊断解释，不自动放宽条件重跑。

独立核验按本次验证目标选用，不是每次普通运行的前置要求。若使用另写的脚本，说明它是否保留原始顺序、如何处理信号有效期（TTL）、无效更新、区间边界，以及核对了哪些文件、信号和输出。例如“按时间排序并一直沿用最近电压”的脚本，与“保留原序且电压过期后无效”的正式分析不等价；不能仅凭总能量相近就称整项功能已验证。核验只覆盖积分数值时，不扩称已验证事件筛选、跨文件状态和全部质量规则；有差异先定位原因，不改业务条件去迎合核验值。
