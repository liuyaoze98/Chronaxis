# Chronaxis 0.1.0.dev6

[English](release-notes-0.1.0.dev6.en.md)

> 0.1.0.dev6 开发预览版；本文说明本版变更、安装方法和已验证的支持范围。

本版继续提高 ASC/BLF 积分的速度，并修正 dev5 连续分卷并行积分中的一处错误：前后文件中同一报文的实际帧型不同时，dev5 可能直接给出数值，本版改为与通用计算流程一样报错（见下文“修正”）。分析配置继续使用整数 `config_version: 4`；公开 API、配置字段和结果格式没有改变，已有配置无需修改。

## 更多积分可以走直接积分和并行积分

| 改进 | 使用时的变化 |
|---|---|
| 固定间隔与 DBC 周期 | dev5 中只有按实际帧间隔（`actual`）计算的积分能使用同一报文的直接积分和连续分卷的并行积分。本版中，全部积分都使用同一个固定间隔（`fixed`），或都使用 DBC 周期（`dbc`）时，也可以使用这两条路径。前提是计时驱动为积分表达式引用的信号（未填写 `driver` 时，程序自动选出的驱动就是这样）；DBC 周期取本次加载的 DBC 中该报文的周期。多项积分混用不同间隔、使用不同的固定值，或以其他报文的信号作计时驱动时，仍沿用通用计算流程。 |
| 按时间归并的多文件（`time_order`） | dev5 中，`time_order` 的积分全部由主进程完成。本版满足直接积分条件时，文件工作进程把每个文件同一时刻的报文整理成组；主进程在全部文件读完后，按时间和文件顺序合并各组，再按原规则求值和累计。进程上限为 1 时也适用。 |
| `time_order` 的读取暂存 | 主进程收取各文件的数据块时不再完整解码，只在归并读回时解码一次。这一项也作用于不满足直接积分条件的 `time_order` 任务，但提速有限，见下文。 |

这些路径由程序自动选择，不需要也不能手动开关；数值结果、跨文件状态、有效期和预算规则不变。完整条件见[连续分卷](../Current/continuous-files.md)和[计算实现](../Current/execution.md#integral-path-conditions)。含计算条件 `condition` 的积分、显式 `reference`/`numpy` 以及 `chronaxis fast` 不使用这些路径。

## 修正：连续分卷并行积分核对前后文件的帧型

dev5 使用 `file_merge: concatenate`、进程上限大于 1 并走并行积分时，没有比较前后文件中同一报文的实际帧型。例如 DBC 把报文标为 CAN FD、配置没有写 `is_fd`，而前一个文件中该报文是 FD 帧、后一个文件中是经典 CAN 帧：单进程的通用计算流程会报错，要求补写 `is_fd`；并行积分却混合两种帧型给出数值，状态显示为完整。

本版的并行积分按文件顺序核对帧型，报出与通用计算流程相同的错误“同一报文绑定匹配多种实际帧，请补充 is_fd”。只有同时满足上述条件的任务受影响，正常输入的结果不变。如果你曾用 dev5 在这种情况下得到结果，请按报错提示在信号绑定中补写对应字段（本例为 `is_fd`）后重新运行。

## 性能结果怎么看

以下数据来自同一台 Windows 电脑（6 核）上相同任务、相同输入和相同结果校验的配对测量，每个场景新旧版本各运行三轮，只说明所测场景。合成数据为 20 万原始帧、十个连续文件；“稀疏”指每 8 帧有 1 条目标报文、1 项积分，“稠密”指每帧都是目标报文、6 项积分。

- 固定间隔与 DBC 周期积分，与 dev5 相比（合成数据，`concatenate`）：1 个进程时稀疏快 1.66—1.92 倍、稠密快 3.44—3.71 倍；4 个进程时稀疏快 2.92—3.08 倍、稠密快 4.26—4.34 倍。例如稠密 ASC 按固定间隔、4 个进程约 115.2→26.6 秒。
- `time_order` 组点并行，与改动前相比（合成数据）：1 个进程时稀疏快 1.38—1.39 倍、稠密快 1.93—2.01 倍；4 个进程时稀疏快 1.86—1.88 倍、稠密快 2.48—2.52 倍。
- 用户提供的十个真实 BLF（文件时间有交叠，只能用 `time_order`；两项无条件积分，固定 10ms 与 DBC 周期结果相同，以下为固定 10ms 的耗时）分两步测量：固定间隔和 DBC 周期进入直接积分时，1 个进程约 146.9→96.6 秒、4 个进程约 104.6→55.2 秒；在此基础上改为组点并行后，分别约 96.9→75.1 秒、55.3→34.5 秒。两步没有在同一轮中直接比较 dev5 与 dev6。
- 不满足直接积分条件的 `time_order` 任务（同一组真实 BLF，带条件积分）：1 个进程约 135.1→126.1 秒，4 个进程约 92.6→88.5 秒，分别只快约 6.7% 和 4.5%。
- 使用文件工作进程时，本机进程树内存峰值比改动前多约 7—37 MiB。

所有场景新旧版本的结果逐行相同，并与独立手算或独立参考值核对一致。以上为各项改动完成时的测量；之后的帧型核对和暂存解码修改没有重新完整计时。

## 手册与 AI 指南

连续分卷和计算实现附录中的积分路径条件已按本版更新（固定间隔、DBC 周期和 `time_order`），并改正了“只按实际帧间隔”“固定或 DBC 周期保持原处理”等过时说法；API 参考补充了新增模块及参数的类型和用途。中英文手册、API 参考和随包 AI 指南已同步。

## 平台与依赖范围

与 dev5 相同：Python `>=3.12,<3.14`；NumPy 在 Python 3.12 为 `>=1.26.3,<2.6`，在 Python 3.13 为 `>=2.1,<2.6`；cantools 为 `>=39.4.3,<46`，jsonschema 为 `>=4.25.1,<4.27`。其他依赖见[安装说明](../Current/installation.md)，精确环境快照见[约束文件说明](../../requirements/README.md)。Linux 工作进程与发布条件仍按[安装说明](../Current/installation.md)执行；本版的性能数据只在 Windows 上测得，没有测量 Linux 上的并行积分性能。

## 安装本版

在新环境中从 PyPI 安装本版并核对自己的任务：

```powershell
py -3.12 -m venv .venv-dev6
.\.venv-dev6\Scripts\python.exe -m pip install "chronaxis==0.1.0.dev6"
.\.venv-dev6\Scripts\python.exe -m pip check
.\.venv-dev6\Scripts\python.exe -m chronaxis guide
.\.venv-dev6\Scripts\python.exe -m chronaxis manual
```

信号有效期、持续条件比较符、积分时间依据和请求输出不会因本轮性能改进自动改变。
